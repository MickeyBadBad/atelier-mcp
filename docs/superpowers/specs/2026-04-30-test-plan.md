This document covers what you actually have to do at the keyboard to know the system works end-to-end, with and without Blender running.

## Layer 1 — Pure-Python regression suite

```bash
cd /Users/mickey/Desktop/personal_projects/FriendsInteriorDesign/blender-mcp
.venv/bin/pytest tests/ -v
```

**Expected:** 235 passing, 0 failing, ~2 sec total. Skip warnings are tolerated. Any failure is a regression — bisect with `git bisect` against the last known-good tag (`v2.3.0-fork.1`).

**What this covers:**
- Module imports + signatures (catches API drift between modules)
- Discovery question bank loads, scoring produces sensible style_match
- Quality gates fire on bad scenes, pass on good scenes
- Procurement records validate, BoM aggregates correctly
- SKU URL parser handles 1688 / Taobao / JD pages
- Style vocab parser handles all 19 published style chapters
- Moodboard prompt builder cites palette hex + Kelvin + style slug
- E2E workflow smoke test runs all stages without crashing
- Every quality-gate Finding has a non-empty handbook citation

**What this does NOT cover:**
- Anything that touches `bpy` (Blender's Python API)
- Anything that hits the real network (image-gen APIs, Sketchfab, claude-in-chrome)
- Real AI client behavior — the question of whether Claude actually *uses* the skills correctly

## Layer 3 — MCP + Blender live

1. Open Blender 4.x or 5.x.
2. Edit → Preferences → Add-ons → Install... → pick `blender-mcp/addon.py`.
3. Tick **Interface: Blender MCP** (the addon should be at `bl_info.version = (2, 3, 0)`).
4. In a 3D viewport, press `N`, switch to the **BlenderMCP** tab, click **Connect to Claude**.
5. Start the MCP server (`uv run blender-mcp`).
6. Connect Claude to the MCP server.

### 3a — Native scene scan + audit

In Claude:

> "Run the interior quality audit in hero mode. The project root is at `/tmp/demo-project`."

Expected sequence:
1. `audit_interior_quality_native(mode="hero", project_root="/tmp/demo-project")`
2. The MCP server sends `interior_audit_scan` to the addon.
3. The addon walks `bpy.data.objects`, `bpy.data.lights`, `bpy.context.scene.cycles.samples`, etc., returns a scene_info dict.
4. The MCP server runs `_gates.run_audit` on the dict, returns findings + status.
5. AI surfaces the findings to you, citing handbook chapters per finding.

Cross-check by opening Blender's system console (Window → Toggle System Console on Windows; on macOS, look at the terminal where Blender was launched). You should see `Getting scene info` / `interior_audit_scan` log lines.

### 3b — Native project scaffold

> "Create a new residential apartment project at `/tmp/demo-project` with three spaces: Living, Bedroom, Kitchen."

Expected sequence:
1. `create_interior_project_native(project_name="demo-project", project_type="residential_apartment", spaces=["Living", "Bedroom", "Kitchen"], project_root="/tmp/demo-project")`
2. MCP writes `/tmp/demo-project/project.json`.
3. MCP sends `interior_project_scaffold` to the addon.
4. Blender's outliner now shows the 11 standard collections + `Living/`, `Bedroom/`, `Kitchen/` under `03_ZONES/`.
5. Scene unit system is set to metric meters.

### 3c — Existing fork tools (regression check)

> "Show me the scene info, then add a 1m cube and place it on the ground."

Expected sequence:
1. `get_scene_info(full=True)`
2. `execute_blender_code(...)` to add a cube
3. `place_on_ground(target_obj="Cube")`

This is just a smoke test that the v2.2.0 base tools still work after the Slice 1-8 additions.

## Layer 4 — Full workflow walkthrough

This is the "did we actually build the thing the user wanted" test. Plan on 30-60 min the first time.

### Setup

1. Open Blender, activate the addon, "Connect to Claude".
2. Start the MCP server.
3. Open a Claude session targeting the MCP server.
4. Have a project in mind (e.g. "redesign my living room", "design a small cafe").

### Walkthrough

**Stage 0 — Discovery**

> "I want to design a [residential apartment / cafe / etc.]. Run the discovery questionnaire."

Claude should invoke `interior-discovery-intake` skill, which loads `discovery.md`, then call `run_discovery_questionnaire`. Answer the 25 questions. At question ~12 Claude should surface its mid-questionnaire inferred-style hypothesis ("looks like you lean toward X"). Confirm or correct. Continue to completion. Verify `taste-profile.json` exists in the project root and contains `recommended_style`.

**Stage 1 — Project scaffold**

> "Create the project."

Claude should call `create_interior_project_native` with the project type from your discovery. Verify Blender's outliner shows the 11 collections + the spaces you chose.

**Stage 2 — Direction + Moodboard**

> "Generate moodboard candidates."

Claude should call `generate_moodboard_candidates(project_root, style_slug, space_type, n=4)` and receive 4 image-gen prompts. It then calls `generate_image_codex` (free) or `generate_image_openai` (paid) on each prompt to actually produce images. Review the 4 candidates.

> "Lock the second one. The palette in that image is closer to what I want."

Claude calls `lock_moodboard(project_root, style_slug, selected_image_paths=["..."])`. Verify `taste-profile.json` now has the four `locked_*` fields.

**Stage 3-4 — Floor plan + 3D scene**

This is the freeform Blender section. Claude uses existing fork tools (`apply_archviz_material`, `setup_lighting`, `place_on_ground`, `set_camera_view`, `download_sketchfab_model`, etc.) plus the new `place_furniture_from_style`:

> "Find a sofa for the living room that matches the locked Scandinavian style and ground it on the floor."

Claude calls `place_furniture_from_style(style_slug="scandinavian", furniture_category="sofa", target_zone_object="Living")`. The tool returns a *plan* (sketchfab query + steps); Claude executes the plan via `search_sketchfab_models` → `download_sketchfab_model` → `place_on_ground`.

**Stage 4.5 — SKU procurement (live web fetch)**

> "Add this 1688 product to the procurement list: https://detail.1688.com/offer/12345.html"

Claude calls `extract_sku_from_url(url=..., page_html="")` → gets a fetch instruction → uses claude-in-chrome MCP tools (`mcp__claude-in-chrome__navigate`, `browser_snapshot`) to fetch the page → calls `extract_sku_from_url` again with `page_html=<captured>` → gets a parsed draft → reviews → calls `record_sku_purchase`.

If claude-in-chrome MCP isn't available, paste the page text manually:

> "I'm pasting the page content. Title is X, price is ¥Y. Record this SKU as a sofa."

**Stage 5 — Render with audit**

> "Render the hero shot."

Claude should call `audit_interior_quality_native(mode="hero")` first. If any 🔴 hard gates fire, Claude surfaces the citation and refuses to render. Fix the gates (add lighting layers, swap to AgX color management, etc.) and try again. Once clean:

> "OK, render."

Claude calls `render_image(...)` and returns the result.

**Stage 6.5 — BoM**

> "Generate the BoM for the contractor."

Claude calls `generate_bom(project_root, output_format="markdown", write_to=".../bom.md")`. Verify the file exists, has line items grouped by category (sofa / lamp / etc.), and shows total cost in RMB.

### Sanity checks during the walkthrough

- [ ] Every gate-violation message that Claude shows you includes a `(per ...)` handbook citation
- [ ] Claude refuses to claim a finding without sourcing it
- [ ] Style explanations cite real publications (AD, Dezeen, Wallpaper*, named designers) — not generic style-knowledge
- [ ] When Claude doesn't know, it says so — does NOT invent a number
- [ ] Color palette hex values applied to Blender materials match the locked style chapter
- [ ] Kelvin temperatures applied to lights fall inside the locked style's range
